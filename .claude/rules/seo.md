# SEO Configuration

- Site-level SEO params in `services/www/hugo.yaml` under `params`: `description`, `author`, `keywords`
- All blog posts should include a `description` field in front matter (under 160 characters)
- A page's `keywords:` front matter (a list) feeds the keywords meta, the
  related-posts index and, on posts, the `article:tag` metas and the Article
  JSON-LD `keywords`. Templates read it through `.Keywords`; no content uses
  `tags:`.
- JSON-LD comes from `services/www/layouts/_partials/seo.html`: Person + WebSite
  on the home page, ProfilePage on `/about/`, Article on posts, WebPage
  elsewhere, plus a BreadcrumbList (from `.Ancestors`) on every page except the
  home page and the 404.
- The home RSS feed lists only top-level `mainSections` (`site.MainSections`):
  `services/www/layouts/home.rss.xml` is Hugo's embedded `rss.xml` with that
  filter added. `/contact/` sets `outputs` without RSS, so it has no empty feed.
- `robots.txt` is generated by Hugo from `services/www/layouts/robots.txt` template (`enableRobotsTXT: true`)
- `llms.txt` and `llms-full.txt` are **generated by Hugo** — never edit them by
  hand and never add a static copy. The stubs are `services/www/content/llms.md`
  and `llms-full.md` (front matter only; `url:` sets the output path), rendered
  by `services/www/layouts/llms*._outputformat_llmtext_.txt`. Adding a post
  updates both automatically.
- Home, section listings and regular pages each emit an `index.md` Markdown
  mirror (`outputs` in `hugo.yaml` lists all three kinds — a kind that is not
  listed gets no mirror). Each HTML page advertises its mirror with
  `<link rel="alternate" type="text/markdown">` (theme `head.html`). There is
  no `Accept: text/markdown` negotiation and no Worker code in www
  (docs/adr-005-static-headers-no-worker-code.md) — do not add one back.
- Response headers come from a **generated** `public/_headers`, rendered by
  `services/www/layouts/home._outputformat_headers_.txt`: security headers, the
  CSP, `X-Robots-Tag: noindex` on `.md` and `llms*.txt`, and on every response
  outside production (staging builds with `HUGO_ENVIRONMENT=staging`), and a
  year-long `Cache-Control: immutable` on fingerprinted assets (`/js/*` always,
  `/css/*` in production only, where the stylesheet is fingerprinted). Never
  hand-edit it. Unknown paths 404 through `not_found_handling`.
- Legacy URLs are redirected by a **generated** `public/_redirects`, built from
  each page's `aliases:` front matter by
  `services/www/layouts/home._outputformat_redirects_.txt`. Never hand-edit it.
  Top-level `disableAliases: true` in `hugo.yaml` stops Hugo emitting the
  meta-refresh stubs that would otherwise shadow those rules — it is a different
  setting from `pagination.disableAliases`, and both are needed.
- Indexability rules are pinned by `services/www/tests/seo.spec.ts`,
  `services/www/tests/assets.spec.ts` and the post-deploy `verify` job. See
  `docs/seo.md` before changing any of them.
- Share image and favicons are **generated**: edit `services/www/brand/share-image.html`
  or `services/www/assets/brand/favicon.svg`, then run `bun run brand` from
  `services/www` and commit the PNGs and `static/favicon.ico`. Never edit those by
  hand. `params.ogImage` sets the default; a page overrides it with `image:` and
  `imageAlt:` front matter. One partial (`share-image.html`) feeds both the meta
  tags and the Article JSON-LD `image`.
